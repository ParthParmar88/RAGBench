# Evaluation benchmark

The fixed benchmark every experiment is measured against. **The dataset does not
change between experiments.** A version that scores badly is evidence about the
system, not a reason to edit the questions.

## Reproducing it

```bash
python -m evaluation.fetch_corpus      # download + verify the 8 papers
python -m evaluation.ingest_corpus     # ingest via the app's own pipeline
python -m evaluation.generate_dataset  # rebuild dataset/v1.jsonl
python -m evaluation.validate_dataset  # check every case against the corpus
```

`fetch_corpus` verifies each PDF's title against page 1, so a mistyped arXiv id
fails loudly instead of silently substituting the wrong paper. `ingest_corpus`
deliberately routes through `services.ingestion.ingest_pdf` — the same code path
the upload endpoint uses — because a separate ingestion path for benchmarking
would measure something other than the real system.

After changing text extraction or chunking, run `ingest_corpus --reingest`:
ingestion is keyed on the PDF's bytes, which don't change when the *pipeline*
does, so stored chunks would otherwise stay stale.

## Corpus

Eight arXiv IR/NLP papers → **445 chunks, 120 pages**. Chosen so the retrieval
experiments are *falsifiable*: dense with exact identifiers (`ColBERT`,
`nDCG@10`, `SST-2`, `MS MARCO`), because hybrid retrieval can only demonstrate a
win where exact-token matching beats semantic similarity. On flowing prose it
would look like a failure however well it was built.

PDFs are fetched, never committed. `corpus/manifest.json` records SHA-256
checksums so the corpus is reproducible without redistributing anything.

## Dataset — 75 cases

| Category | n | What it tests |
|---|---|---|
| `factual` | 16 | A fact stated in one passage. The easy baseline. |
| `semantic` | 15 | Conceptual, low vocabulary overlap. Vector search should win. |
| `keyword` | 14 | Turns on an exact identifier. **Experiment 003 must move this.** |
| `multi_chunk` | 10 | Needs 2+ passages from one paper. The Experiment 002 signal. |
| `multi_document` | 6 | Needs 2+ papers. Tests whether top-k is spent on one document. |
| `ambiguous` | 6 | Underspecified. Tests hedging over confident guessing. |
| `unanswerable` | 8 | Not in the corpus. Catches confident hallucination. |

Document coverage runs 6–10 questions per paper.

## Ground truth is anchored to quotes, not chunk ids

Chunk ids are an artefact of one chunking strategy. Re-ingesting with different
boundaries renumbers everything, and Experiment 002 changes chunking on purpose
— so a benchmark keyed on chunk ids would break exactly when it is needed most.

A quote is a property of the *document*. "Was a passage containing this sentence
retrieved?" is answerable under any chunking strategy, which keeps context
recall comparable across every experiment.

Every quote is verified to appear verbatim in the ingested corpus. Matching
folds extraction artefacts (line breaks, ligatures, typographic dashes, edge
ellipses) but never reorders, stems, or drops words — so a paraphrase still
fails. `tests/test_dataset_schema.py` pins both edges: real quotes must match,
paraphrases and altered numbers must not.

## How the cases were built

Generated from real passages, so every ground truth traces to text that exists.
Each case is checked immediately; a quote that wasn't copied verbatim is retried,
then dropped. **26 of 101 generated candidates were rejected** — the check is
doing real work, not decorating the pipeline.

Two filters were added after reading the first batch, because both defects
produced cases that were structurally valid and semantically worthless:

- **Bibliography chunks excluded.** They produced questions like "what is the
  arXiv identifier of the 2017 summarization preprint?" — citation-list lookup,
  not comprehension. Detected by combined year *and* venue-marker density;
  citation-dense "Related Work" prose is year-dense but venue-free, so it
  survives. A year-only threshold would have discarded 26% of the corpus.
- **Scaffold leakage rejected.** Pair prompts label passages "A" and "B", and
  that leaked into questions ("how does the method in Passage A compare with
  Passage B?"). Unanswerable by a real user and by the system, which has no such
  concept.

The `ambiguous` and `unanswerable` cases are hand-written. They cannot be
generated from the corpus, because their whole point is to sit outside it.

## Known limitations

Stated here rather than in the final write-up, so they can't be quietly dropped.

1. **Generator and system share a model family.** Questions are generated by
   `gpt-4o-mini`, which also answers them. This risks a benchmark shaped to the
   model's own phrasing habits, which flatters it. Mitigated but not eliminated
   by the verbatim-quote grounding and hand-written adversarial cases.
2. **`multi_document` is thin at 6 cases.** Pairs reject at roughly twice the
   rate of single passages, and the cross-document pair list is short. Enough for
   a directional signal, not for a confident effect size. Treat movement in this
   category as suggestive.
3. **`ambiguous` cases carry no supporting quotes.** They are graded on answer
   behaviour, not retrieval. Inventing quotes from memory would risk asserting
   text that isn't in the corpus — the exact failure the quote check prevents.
4. **Ground truth is model-written, not expert-written.** Verified against source
   text, but not reviewed by a domain expert.
5. **Dataset generation cost is not in `llm_usage`.** Deliberate: it isn't part
   of the RAG pipeline, and mixing it in would corrupt cost-per-query. The final
   run used ~192k tokens (~$0.04); all iterations together, roughly $0.15.
